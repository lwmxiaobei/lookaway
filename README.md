# mac-duo

转头就糊屏。用 AirPods 的空间音频陀螺仪判断你有没有正对着 Mac 屏幕，一旦转开就给整屏盖上毛玻璃，转回来自动散开。

灵感来自 [@bryllim_ 的演示](https://x.com/bryllim_/status/2099049704822907277)。

## 需要什么

- macOS 14 或更新
- 带头部追踪的 AirPods：AirPods 3 / AirPods Pro / AirPods Max
- Xcode 命令行工具（`swift` 可用即可）

## 跑起来

```bash
make run        # 打包 + 启动，菜单栏会出现一只眼睛
make install    # 装进 /Applications 并启动
make test       # 跑核心逻辑的单元测试
```

首次启动系统会询问「动作与体能训练」权限，必须允许，否则读不到 AirPods 姿态。

戴上 AirPods，点菜单里的 **校准正前方**，盯着屏幕中央出现的倒计时看完。之后视线转出屏幕范围，所有屏就会糊掉。

校准必须走倒计时，不能点完就采样——点菜单的时候你的头是转向菜单栏的（主屏左上角），当场采样会把偏了三十几度的朝向当成正前方。

菜单顶部两行是实时的：第一行显示当前偏离角度，第二行显示屏幕数和视野边界。菜单开着的时候转头，数值会跟着动——用它来判断该把观看距离和边缘余量调到多少。

## 菜单里能调什么

| 项 | 说明 |
|---|---|
| 暂停 / 启用遮蔽 | 总开关 |
| 校准正前方（倒数 3 秒） | 屏幕正中会出现倒计时，盯着它，数完才采样 |
| 预览遮蔽效果 | 遮 3 秒，用来确认视觉效果 |
| 观看距离 | 40~80 cm，默认 60。决定屏幕阵列张开多大角度 |
| 边缘余量 | 0° / 6° / 12° / 20°，默认 12。阵列边缘之外再放宽多少才算「转开了」 |
| 模糊强度 | 轻 / 中 / 重 |
| 开机时启动 | 走 `SMAppService` |

## 它是怎么工作的

```
CMHeadphoneMotionManager ─yaw─► BaselineTracker ─偏离角─┐
                                                       ├─► AttentionPolicy ─遮/不遮─► OverlayController
NSScreen + CGDisplayScreenSize ─► ScreenGeometry ─视野─┘
```

- **BaselineTracker** 维护「正对屏幕」的基准。AirPods 的 yaw 是相对启动姿态的，而且会缓慢漂移，所以除了手动校准，还会在判定为正对屏幕的小角度区间内让基准以一阶低通慢慢跟随。真的转头时绝不跟随——否则转过去待一会儿基准就跟过去、遮罩自己撤了。
- **ScreenGeometry** 算出所有显示器合起来张开多大的水平角。这一步必须走物理毫米而不是逻辑坐标：不同屏的 DPI 不一样，同样的逻辑宽度对应的实际宽度可能差一倍。显示器插拔会自动重算。
- **HeadOrientation** 做两件容易错的换算，见下。
- **AttentionPolicy** 是纯状态机，判断视线有没有落在这个角度范围内。多屏横排时范围通常不对称，所以左右边界分开表达。另外负责迟滞（出界才遮，回到边界内侧 8° 才撤）和停留时间（出界持续 0.25s 才遮），挡住边界抖动和「快速扫一眼」的误触发。不碰任何 UI，全部可单测。
- **OverlayController** 给每块屏幕一个无边框窗口，内容是 `NSVisualEffectView(blendingMode: .behindWindow)`——模糊的是窗口背后的真实画面，由合成器直接完成，**不需要屏幕录制权限**，也几乎不耗电。窗口鼠标穿透，遮住时照样能操作底下的 App。显示器插拔会自动重建。

### 多屏怎么算

遮罩是**全部屏幕一起**遮或一起放开，判据是「视线还在不在屏幕阵列上」——看哪块屏都不算转开，头转出整个阵列才全糊。

代价是屏越多门槛越高。三屏横排（14" + 两台 24"，60cm 距离）阵列占 ±49° 视线角，换算成头部转角 ±34°，加默认 12° 余量后 ±46° 触发。想更灵敏就把边缘余量调到 0°，或把观看距离调大（等于告诉程序屏幕张角更小）。

留这 12° 余量是因为外接屏常常朝用户内扣摆放，实际角度比按共面算出来的更大。

### 三个反直觉的地方

**yaw 的方向和屏幕坐标是反的。** CoreMotion 的 attitude 是右手系，yaw 绕垂直轴逆时针为正，也就是向左转头 yaw 增大；而屏幕坐标向右为正。不翻过来，左右边界会整个对调——表现为你看右屏时反而触发遮罩。

**`NSScreen.main` 不是主显示器。** 它返回的是当前有 key window 的那块屏，会跟着焦点乱跑。拿它当几何原点，视野会算成以某块外接屏为中心的歪值（实测出现过 `-54.1° ~ +90.1°`）。主显示器是 `frame.origin == .zero` 的那块。

**头转的角度小于视线角度。** 人看侧面目标时眼球先动、头跟不到位，头部大约只贡献七成。直接拿屏幕张角当头部转动阈值会系统性偏大，该遮的时候不遮。所以边界要先乘 `headContribution`（0.7）再加余量。

### 两个刻意的设计

**窗口层级压在状态栏菜单之下（100，菜单是 101）。** 遮罩盖得住菜单栏、Dock 和全屏 App，但永远盖不住我们自己的下拉菜单——万一误触发，你还看得见去哪里关掉它。

**姿态数据一断流就立刻放开屏幕。** 摘下 AirPods、蓝牙断开、传感器出错，任何一种情况下 1.5 秒看门狗都会撤掉遮罩。否则屏幕会永远糊着，用户没法自救。

## 开发

```
Sources/DuoCore/     纯逻辑，不依赖 AppKit/CoreMotion，全部有单测
Sources/MacDuo/      AppKit 层：追踪器、遮罩窗口、菜单栏
scripts/bundle.sh    组装 .app（写 Info.plist + 签名）
```

诊断用的三个 target：

```bash
make selftest        # 启动后自动遮 3 秒，没戴 AirPods 也能验证遮罩链路
make debug-overlay   # 每块屏涂不同颜色并标注编号，遮 15 秒。分辨「窗口没到位」还是「毛玻璃没渲染」
make trace           # 把每帧的 yaw、基准、偏离角、判定边界写进 /tmp/macduo-trace.csv
```

`make trace` 是定位误触发的主力——零点偏了、边界算歪了、还是陀螺仪在漂，读一遍 CSV 就能分清，不用猜。

`make selftest` 的秒数可以调：

```bash
open build/mac-duo.app --env MACDUO_SELFTEST=1 --env MACDUO_SELFTEST_SECONDS=12
```

注意：**不能**直接执行 `build/mac-duo.app/Contents/MacOS/MacDuo`。那样 TCC 会把终端当作负责进程、查不到 `NSMotionUsageDescription`，进程会被系统直接杀掉。一律用 `open`。

## 还没做

摄像头兜底、只模糊侧边而非整屏、按 App 白名单、全局快捷键。

还有一个更贴多屏的方案没做：**逐屏扇区**——每块屏各占一个角度区间，你看哪块哪块清晰、其余遮住。隐私保护比现在彻底得多，代价是要逐屏校准，而且看左屏时右屏会糊掉。
